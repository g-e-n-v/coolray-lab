# geely-new-coolray-vn/ — Flash package for the Geely New Coolray VN (IHU689G)

Independently signed update package for the car's **IHU689G** head unit, with a
payload that matches the checkbuy package
`community-pack/install_market/3C5625_SW0SX11_coolray_g/`
(IHU628G — the closest baseline, see the original README.md §3–5).

## 1. How does this package differ from the coolray_g checkbuy package?

Compared to the `coolray_g` checkbuy package, this one differs in 3 things:

1. **USB folder name**: `3C6525_SW0A5LV` = the car firmware's targetName
   (`3C6525_SW0A5LV0126H102000000`) — the 「U盘升级」 menu matches exactly this name.
2. **4 metadata lines**:
   ```
   post-build=GEELY/full_IHU689G/IHU689G:9/PQ2A.190405.003/20:user/test-keys
   post-build-incremental=20
   post-timestamp=<build time>
   pre-device=IHU689G
   ```
3. **No `CommunityPackMarket.apk`** (removed from the payload; only `Stagelight.apk`
   is kept in `/system/app/`).

Everything else is **byte-for-byte identical**: `Stagelight.apk`, `update-binary`,
`updater-script`, `otacert` (identical DER), signed with the same key the car's
recovery already accepted when flashing on 21/09/2026 — AOSP platform testkey
serial `B3998086D056CFFA` (SHA-1, RSA-2048). Behavior on the car: installs
StageLight into `/system/app/`, creates `/data/misc/coolray` (0777), and ends with
`GOTOVO`.

Important: as of 09/10/2026 **`payload/` is the self-contained source of truth** —
every change relative to the original checkbuy package lives permanently inside
payload/ (its git history serves as the change log), and the build pipeline reads
nothing outside this `geely-new-coolray-vn/` directory. `referrences/` (the
original checkbuy package, logs, research) is used for cross-checking only.

## 2. Directory layout

Organized by role — one place for each thing; the pipeline flows one way from
source → payload → dist:

```
geely-new-coolray-vn/
├── README.md                    ← this file (overview + process)
├── docs/
│   └── flash-adb-unlock.md      ← flash + ADB guide (verified on the car)
├── keys/                        ← OTA signing keys (accepted by the car's recovery)
│   ├── aosp_platform.x509.pem   #   x509, serial B3998086D056CFFA
│   └── platform.pk8             #   PKCS#8 private key
├── vendor/signapk/              ← third-party signer (vendored, not hand-written)
│   ├── SignApk.java             #   AOSP SignApk, patched to drop conscrypt
│   ├── SignApk.jar              #   (runs on Java 17/ARM)
│   ├── bcprov-jdk14-1.59.jar    #   BouncyCastle deps
│   └── bcpkix-jdk14-1.59.jar
├── scripts/                     ← build pipeline (runs from payload/, self-contained)
│   ├── build-update.sh          # (1) zip + sign + verify + write md5 (+ deploy to USB)
│   ├── embed-app.sh             #     embed an APK as a system app into payload/
│   └── verify-ota-signature.py  #     verify the signature like recovery's verify_file()
├── payload/                     ← SOURCE OF TRUTH (self-contained, edit directly — see
│   ├── README.md                #   payload/README.md: per-file editing rules,
│   ├── META-INF/…               #   how to embed/remove apps, warnings)
│   └── system/app/Stagelight/
└── dist/                        ← DISTRIBUTION ARTIFACT — copy the subfolder as-is
    └── 3C6525_SW0A5LV/          #   to the ROOT of a USB stick (FAT32), keep the name
        └── OS/
            ├── update.zip
            └── md5.txt          # 32 hex characters, NO trailing newline
```

Conventions:

| Folder         | Role                          | Who creates / edits it                            |
| -------------- | ----------------------------- | ------------------------------------------------- |
| `docs/`        | docs, guides                  | hand-written                                     |
| `keys/`        | signing material              | fixed; do NOT commit any other private keys      |
| `vendor/`      | vendored third-party tools    | only patch when necessary (document the reason)  |
| `scripts/`     | pipeline code                 | hand-written — all payload customization goes here |
| `payload/`     | self-contained source         | edited by hand / `embed-app.sh`; commit on change |
| `dist/`        | final (flashable) artifact    | generated by `build-update.sh`                   |

Note: if `payload/` is ever lost, restore it from git
(`git checkout -- geely-new-coolray-vn/payload`) — the git history of payload/
is the change history of the update package.

## 3. Verify before flashing

```bash
# 1) MD5 matches md5.txt (32 hex chars, no newline)
md5 dist/3C6525_SW0A5LV/OS/update.zip; cat dist/3C6525_SW0A5LV/OS/md5.txt

# 2) Whole-file signature is valid (exact algorithm of Android 9 recovery)
python3 scripts/verify-ota-signature.py dist/3C6525_SW0A5LV/OS/update.zip
# PASS: whole-file signature verified (SHA-1) against otacert serial=0xb3998086d056cffa
```

## 4. Rebuilding (when you need to change the timestamp / embed another APK)

```bash
# Embed another app (optional):
./scripts/embed-app.sh <app.apk> [AppName]  # copy + set_metadata in updater-script

# Build:
./scripts/build-update.sh                 # → dist/3C6525_SW0A5LV/OS/
./scripts/build-update.sh deploy BOBBY    # + copy to /Volumes/BOBBY
                                          # (auto-removes macOS ._ junk files, prints menu code)
```

Requirements: Java 17 (`brew install openjdk@17`) + python3 (`cryptography`).
For the flashing procedure, engineering menu codes, ADB routes, and brick
warnings, see `docs/flash-adb-unlock.md`.
